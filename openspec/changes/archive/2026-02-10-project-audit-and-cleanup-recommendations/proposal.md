## Why

Repository root contains many legacy and duplicate documents that make navigation and maintenance harder. A focused cleanup is needed now to reduce cognitive load, preserve only current sources of truth, and create a clear plan for ongoing development.

## What Changes

- Audit repository structure with focus on root-level files and documentation density.
- Define retention policy for documents: keep canonical guides, archive historical notes, remove obsolete duplicates.
- Produce a prioritized cleanup plan with explicit keep/archive/delete recommendations.
- Establish a minimal project map so contributors can quickly understand where code, docs, and workflows live.
- Align planning artifacts with current workflow (OpenSpec + selected core docs) to avoid roadmap drift.

## Capabilities

### New Capabilities
- `repo-hygiene-governance`: Defines standards and workflow for keeping repository structure and docs clean over time.
- `project-orientation-map`: Defines a canonical orientation guide for understanding project structure and entry points.

### Modified Capabilities
- None.

## Impact

- Affected systems: repository documentation and project planning workflow.
- Affected files: root-level markdown files, planning docs (`README.md`, `ROADMAP.md`), and OpenSpec artifacts.
- Dependencies: no runtime dependency changes; process/documentation impact only.
